# Decryption service invariants

Each ID names a guarantee and links to direct assertions. Keep IDs stable.
A recorded rehearsal is distinct from an automated test and applies only to its
recorded configuration. The service spec states the trust assumptions these tests cover.

## Decryption service

| ID | Invariant | Coverage |
| --- | --- | --- |
| SPR-CORE-01 | Only a canonical, non-identity, prime-order Ed25519 address gets service keys. | Lookup and decrypt reject malformed, off-curve, small-order, mixed-order and noncanonical addresses. Forged, missing, and noncanonical signatures fail even for empty batches. [Owner authorization](../enclave/tests/unit/owner_authorization.rs) |
| SPR-CORE-02 | The address and deployment note seed determine the service keys. | Fixed derivation vectors, address and seed separation, and agreement across replicas. [Derivation](../enclave/tests/unit/key_derivation.rs) · [Release binding](../enclave/tests/unit/release_binding.rs) |
| SPR-CORE-03 | The owner approves the ordered batch for one network and release. | A change to the signer, request ID, item field, item order, item count, network, or response key invalidates approval. The enclave rejects mismatched release pins, unsupported versions, and unknown fields. Rust and TypeScript agree on the digest and signed Solana message. The SDK rejects a signature for another owner or altered message before transport. [Owner approval client](../sdk/tests/client/decryption.test.ts) [Owner authorization](../enclave/tests/unit/owner_authorization.rs) · [Release binding](../enclave/tests/unit/release_binding.rs) · [Rust vectors](../protocol/tests/unit/decryption_request_binding.rs) · [SDK vectors](../sdk/tests/protocol/decryption.test.ts) |
| SPR-CORE-04 | Only the signed response key opens the reply. | A second key cannot open the reply or replace the signed key even during a permitted retry. Invalid and compressed response keys fail. [Response privacy](../enclave/tests/unit/response_privacy.rs) |
| SPR-CORE-05 | The enclave uses only the verified signer's viewing key. | An output for another address yields unrelated bytes. Wrong ephemeral key encoding, low-order points, malformed salt, and invalid slots fail the entire batch. Ring deposits use their own cipher domain and require slot zero. [Output handling](../enclave/tests/unit/output_handling.rs) |
| SPR-CORE-06 | Batch and byte limits apply before work crosses the next boundary. | The enclave accepts 256 items and rejects 257 during decoding, before hashing, signature verification or a clock read. It bounds HTTP bodies and encrypted results. The SDK rejects malformed slots, labels and salts before approval and splits at 256 or on the serialized byte limit before signing. It preserves order and rejects incomplete results. [Request decoding](../protocol/tests/unit/decryption_request_binding.rs) · [Enclave batches](../enclave/tests/unit/output_handling.rs) · [HTTP limits](../enclave/tests/unit/http_and_ping.rs) · [Result limit](../enclave/tests/unit/app_proof_signature.rs) · [SDK batching](../sdk/tests/client/items.test.ts) · [Item validation](../sdk/tests/client/keys.test.ts) · [Before signing](../sdk/tests/client/decryption.test.ts) |
| SPR-CORE-07 | The SDK opens only the authenticated reply to its request. | Wrong proof type, version, signature, request ID, request digest, result digest, operation, scheme, or signing replica fails. The SDK rejects oversized ciphertext, the wrong response key, noncanonical plaintext, and unknown proof fields. [Operation replies](../sdk/tests/connection/operations.test.ts) |
| SPR-CORE-08 | Decrypted notes must match their indexed commitments. | The SDK opens empty and nonempty batches with separate approvals. The handle pins its owner and nullifier secret and rejects requests for an unheld viewing key before remote approval or local transaction key derivation. Every plaintext must match the corresponding ciphertext length. The wallet discards a note with a mismatched commitment. [SDK reply checks](../sdk/tests/client/decryption.test.ts) · [Direct E2E](../example/tests/decryption.test.ts) · [Localnet example](../example/index.ts) |
| SPR-CORE-09 | Destroying the SDK key handle cancels decryption and proving, wipes pending derived keys, and prevents further key operations. | Pending decrypt and proof calls reject even if their provider returns late. The SDK passes cancellation to the prover. Derived bytes and transaction keys that have yet to return are cleared. A cancelled open cannot create a key handle. [SDK keys](../sdk/tests/client/keys.test.ts) · [Handle creation](../sdk/tests/client/decryption.test.ts) |
| SPR-CORE-10 | The enclave wipes request JSON after parsing. It serializes replies into one bounded, zeroizing output buffer and wipes the plaintext result before the final deadline check. | Both reply variants keep their canonical wire bytes. Tests cover empty items, hex chunk boundaries and the plaintext size ceiling. [Reply encoding](../protocol/tests/unit/decryption_result_encoding.rs) · [Encrypted reply limit](../enclave/tests/unit/app_proof_signature.rs) |
| SPR-CORE-11 | The enclave processes a decrypt only while the signed deadline is in the next 120 seconds by its clock. | Missing, malformed and altered deadlines fail. An otherwise valid approval fails beyond that window, at or after expiry, when the clock cannot be read, and when expiry passes during the operation. Public key lookup requires no clock read. Both clients sign a deadline bounded by 60 seconds and the verified session. [Wire checks](../protocol/tests/unit/decryption_request_binding.rs) · [Enclave checks](../enclave/tests/unit/owner_authorization.rs) · [TypeScript wallet](../sdk/tests/client/decryption.test.ts) · [Rust wallet](https://github.com/helius-labs/privacy-rings/pull/652) |
| SPR-CORE-12 | The TypeScript exchange checks cancellation before decrypting an authenticated reply. It clears temporary secrets and decrypted reply bytes that it owns. | Cancellation during a stalled or completing policy check discards the reply. Both valid and invalid UTF-8 clear the opened buffer. A byte-order mark breaks canonical JSON. Envelope key material is cleared after success and failure. [Reply tests](../sdk/tests/connection/operations.test.ts) · [Envelope tests](../sdk/tests/crypto/qos.test.ts) |
| SPR-CORE-13 | Wallet scans discard notes with low-order transaction viewing keys before requesting decryption. | A tagged output with a low-order key never reaches the key holder. The Rust scan still recovers an adjacent valid note. [Rust scan](https://github.com/helius-labs/privacy-rings/blob/e275315cff1c867cc85af471dc63722c16b96d68/sdk-libs/transaction/tests/decryption.rs#L1313) · [TypeScript scan](https://github.com/helius-labs/privacy-rings/blob/10aa58914c3085f45d64d2dadaa8f4595a700a32/sdk-libs/ts/test/wallet-sync.test.ts#L1904) |
| SPR-CORE-14 | TypeScript wallet sync owns and clears returned plaintext buffers. Cancellation prevents wallet state from committing. | Successful, malformed, rejected and cancelled batches clear owned plaintext. Wallet state stays unchanged on cancellation before scanning or during decryption. [Batch cleanup](https://github.com/helius-labs/privacy-rings/blob/10aa58914c3085f45d64d2dadaa8f4595a700a32/sdk-libs/ts/test/key-memo.test.ts#L68) · [Wallet state](https://github.com/helius-labs/privacy-rings/blob/10aa58914c3085f45d64d2dadaa8f4595a700a32/sdk-libs/ts/test/wallet-sync.test.ts#L1195) |
| SPR-CORE-15 | The SDK reads untrusted HTTP bodies through a size-bounded stream reader. | A missing stream yields an empty body. Reusing a chunk buffer preserves bytes already copied. Overflow or cancellation stops the read. [HTTP reader tests](../sdk/tests/connection/http.test.ts) |

## Release and transport

| ID | Invariant | Coverage |
| --- | --- | --- |
| SPR-QOS-01 | Hosted staging submits the reviewed launch configuration. Only the authenticated, matching deployment can supply a release pin. | Turnkey receives a private copy of the validated descriptor and only inherits its credential and replica-count environment inputs. The tool checks the authenticated image digest, runtime, measured executable, launch arguments, debug mode, and Quorum key before live attestation. A wrong image digest, altered manifest, or failed proof keeps the pin from being written. [Stage tests](../xtask/tests/stage.rs) · [CLI command tests](../xtask/tests/tools.rs) · [Policy tooling](../xtask/tests/policy.rs) · [Connection](../sdk/tests/connection/connect.test.ts) |
| SPR-QOS-02 | Release policy authorization requires a valid threshold of distinct keys. | Signed policies fail on another network, expiry, revocation, tampering, or missing signatures. Duplicate signer IDs do not count. Malformed thresholds and the same key under two authority IDs are rejected. [Rust conformance](../protocol/tests/conformance.rs) · [SDK conformance](../sdk/tests/protocol/conformance.test.ts) · [SDK release policy](../sdk/tests/protocol/releases.test.ts) |
| SPR-QOS-03 | Discovery and replies are bound to the running QOS replica. | Startup requires the QOS v2 JSON envelope and matches the Quorum key against its manifest. The SDK checks a current signed ping, the Nitro root and COSE signature, pinned PCR0–3, PCR17, manifest, and replica key. [QOS loader](../enclave/tests/unit/qos_startup.rs) · [Ping](../sdk/tests/connection/connect.test.ts) · [Boot Proof](../sdk/tests/attestation/boot-proof.test.ts) · [Root certificate](../sdk/tests/attestation/boot-proof-chain.test.ts) |
| SPR-QOS-04 | Release checks bound untrusted discovery and terminate stalled verification. | The release bridge uses the SDK's bounded discovery reader. A single signal covers ping, Boot Proof lookup, and attestation verification. Release and image checks share one deadline for reading output and waiting for the subprocess. They stop and reap the subprocess on timeout or after reading more than 4 MiB. [Live verification](../sdk/tests/connection/connect.test.ts) · [Release subprocesses](../xtask/tests/tools.rs) |
| SPR-QOS-05 | Canonical wire bytes agree across Rust, TypeScript, and QOS. | Strict JSON, UTF-16 key ordering, numeric and hex encodings, P-256 low-S signatures, and size checks. The SDK reproduces the shared envelope vector, and Turnkey's `qos_p256` opens it and rejects the wrong key or a truncated frame. The public health route exposes readiness only. [Wire fixtures](../protocol/tests/conformance.rs) · [QOS interoperability](../protocol/tests/qos_crate_interop.rs) · [SDK conformance](../sdk/tests/protocol/conformance.test.ts) |
| SPR-QOS-06 | One SDK deadline covers verification and every decrypt batch. | The caller timeout applies to the whole call. Shared verification survives one caller timing out. Session expiry cancels approval and discards late signatures. Hosted Boot Proofs use the clock after lookup. The release must be current when the session returns, when a request is sent, and when an authenticated reply is opened. The SDK wipes the response key. [Owner approval](../sdk/tests/client/decryption.test.ts) · [Session lifetime](../sdk/tests/connection/session.test.ts) · [HTTP limits](../sdk/tests/connection/http.test.ts) · [Boot Proof lookup](../sdk/tests/connection/connect.test.ts) · [Reply validation](../sdk/tests/connection/operations.test.ts) |
| SPR-QOS-07 | Turnkey signs the exact SDK bytes for the expected account. | The adapter uses raw Ed25519 for approvals. It refuses another account's signature and changed transaction messages. [Turnkey signer](../example/tests/turnkey.test.ts) |
| SPR-QOS-08 | Hosted staging records an attempt before creating a deployment. | One checkout serializes staging of the same release. A lost create response keeps the pending record. Recovery checks the original organization and descriptor and verifies the supplied deployment before saving its ID. A confirmed ID survives a later verification failure. [Stage tests](../xtask/tests/stage.rs) |

The tests use fixtures and simulated attestation inputs. The
[service spec](../enclave/SPEC.md#key-custody-and-trust) describes the trust
required of Quorum operators and the release authorities.

## Mainnet release controls

| ID | Invariant | Coverage |
| --- | --- | --- |
| SPR-OPS-01 | An unapproved build cannot supply a production manifest. | The operator tool requires the reviewed source commit, expected GitHub workflow, protected source ref, and immutable image digest. [Provenance checks](../xtask/tests/stage.rs) |
| SPR-OPS-02 | The staged mainnet release cannot switch a serving app or replace the known Quorum domain. | Candidate selection permits the first deployment or resumption of the same deployment. The operator tool rejects a shared devnet identity, a different Quorum key, and a one-share manifest. [Release staging](../xtask/tests/stage.rs) · [Approved deployment](../xtask/tests/policy.rs) |
| SPR-OPS-03 | A release bundle cannot choose its own mainnet trust anchors. | The SDK binds the policy to the independently pinned domain, Quorum key, distinct authority threshold, maximum lifetime, and revocation floor. [Mainnet pins](../sdk/tests/protocol/mainnet-release.test.ts) |
| SPR-OPS-04 | The example validates RPC genesis before loading signing credentials. | Preflight rejects mainnet configuration before any network call. It rejects mainnet genesis in both modes and accepts only the devnet genesis for hosted mode. Local mode requires loopback. [Example preflight](../example/tests/setup.test.ts) |
