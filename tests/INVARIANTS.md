# Decryption service invariants

Each ID names a guarantee and links to direct assertions. Keep IDs stable.
A recorded rehearsal is distinct from an automated test and applies only to its
recorded configuration. Track uncovered release controls in the [internal audit](AUDIT.md).

## Decryption service

| ID | Invariant | Coverage |
| --- | --- | --- |
| SPR-CORE-01 | Only a signer-capable Solana address gets service keys. | Lookup and decrypt reject malformed, off-curve, and small-order addresses. Forged, missing, and noncanonical signatures fail even for empty batches. [Owner authorization](../enclave/tests/unit/owner_authorization.rs) |
| SPR-CORE-02 | The address and deployment note seed determine the service keys. | Fixed derivation vectors, address and seed separation, and agreement across replicas. [Derivation](../enclave/tests/unit/key_derivation.rs) · [Release binding](../enclave/tests/unit/release_binding.rs) |
| SPR-CORE-03 | The owner approves the ordered batch for one network and release. | A change to the signer, request ID, item field, item order, item count, network, or response key invalidates approval. The enclave rejects mismatched release pins, unsupported versions, and unknown fields. Rust and TypeScript agree on the digest and signed Solana message. [Owner authorization](../enclave/tests/unit/owner_authorization.rs) · [Release binding](../enclave/tests/unit/release_binding.rs) · [Rust vectors](../protocol/tests/unit/decryption_request_binding.rs) · [SDK vectors](../sdk/tests/protocol/decryption.test.ts) |
| SPR-CORE-04 | Only the signed response key opens the reply, including after replay. | A second key cannot open the reply or replace the signed key. Invalid and compressed response keys fail. [Response privacy](../enclave/tests/unit/response_privacy.rs) |
| SPR-CORE-05 | The enclave uses only the verified signer's viewing key. | An output for another address yields unrelated bytes. Wrong ephemeral key encoding, low-order points, malformed salt, and invalid slots fail the entire batch. Ring deposits use their own cipher domain and require slot zero. [Output handling](../enclave/tests/unit/output_handling.rs) |
| SPR-CORE-06 | Batch and byte limits apply before work crosses the next boundary. | The enclave accepts 256 items, rejects 257, and bounds HTTP bodies and encrypted results. The SDK splits at 256 or on the serialized byte limit before signing or sending an oversized request. It preserves order and rejects incomplete results. [Enclave batches](../enclave/tests/unit/output_handling.rs) · [HTTP limits](../enclave/tests/unit/http_and_ping.rs) · [Result limit](../enclave/tests/unit/app_proof_signature.rs) · [SDK batching](../sdk/tests/client/items.test.ts) · [Before signing](../sdk/tests/client/decryption.test.ts) |
| SPR-CORE-07 | The SDK opens only the authenticated reply to its request. | Wrong proof type, version, signature, request ID, request digest, result digest, operation, scheme, or signing replica fails. The SDK rejects oversized ciphertext, the wrong response key, noncanonical plaintext, and unknown proof fields. [Operation replies](../sdk/tests/connection/operations.test.ts) |
| SPR-CORE-08 | Decrypted notes must match their indexed commitments. | The SDK opens empty and nonempty batches with separate approvals. It discards a note with a mismatched commitment. The localnet example checks the amount and note count after claim and sweep. [SDK keys](../sdk/tests/client/keys.test.ts) · [Direct E2E](../example/tests/decryption.test.ts) · [Localnet example](../example/index.ts) |

## Release and transport

| ID | Invariant | Coverage |
| --- | --- | --- |
| SPR-QOS-01 | Only the reviewed deployment can supply a release pin. | The tool checks the authenticated image digest, runtime, measured executable, launch arguments, debug mode, and Quorum key before live attestation. A wrong image digest, altered manifest, or failed proof keeps the pin from being written. [Policy tooling](../xtask/tests/policy.rs) · [Connection](../sdk/tests/connection/connect.test.ts) |
| SPR-QOS-02 | Release policy authorization requires a valid threshold of distinct keys. | Signed policies fail on another network, expiry, revocation, tampering, or missing signatures. Duplicate signer IDs do not count. Malformed thresholds and the same key under two authority IDs are rejected. [Rust conformance](../protocol/tests/conformance.rs) · [SDK conformance](../sdk/tests/protocol/conformance.test.ts) · [SDK release policy](../sdk/tests/protocol/releases.test.ts) |
| SPR-QOS-03 | Discovery and replies are bound to the running QOS replica. | Startup requires the QOS v2 JSON envelope and matches the Quorum key against its manifest. The SDK checks a current signed ping, the Nitro root and COSE signature, pinned PCR0–3, PCR17, manifest, and replica key. [QOS loader](../enclave/tests/unit/qos_startup.rs) · [Ping](../sdk/tests/connection/connect.test.ts) · [Boot Proof](../sdk/tests/attestation/boot-proof.test.ts) · [Root certificate](../sdk/tests/attestation/boot-proof-chain.test.ts) |
| SPR-QOS-04 | Release checks bound untrusted discovery and terminate stalled verification. | The release bridge uses the SDK's bounded discovery reader. A single signal covers ping, Boot Proof lookup, and attestation verification. Cargo kills and reaps timed-out check subprocesses and caps captured output. [Live verification](../sdk/tests/connection/connect.test.ts) · [Release subprocesses](../xtask/tests/tools.rs) |
| SPR-QOS-05 | Canonical wire bytes agree across Rust, TypeScript, and QOS. | Strict JSON, UTF-16 key ordering, numeric and hex encodings, P-256 low-S signatures, and size checks. The SDK reproduces the shared envelope vector, and Turnkey's `qos_p256` opens it and rejects the wrong key or a truncated frame. The public health route exposes readiness only. [Wire fixtures](../protocol/tests/conformance.rs) · [QOS interoperability](../protocol/tests/qos_crate_interop.rs) · [SDK conformance](../sdk/tests/protocol/conformance.test.ts) |
| SPR-QOS-06 | One SDK deadline covers verification and every decrypt batch. | The caller's timeout or client default applies to the whole call. Shared verification survives one caller timing out. The SDK stops stalled responses and cancelled approvals, wipes the response key, and refuses a request if the release expires during signing. [Client deadline and owner approval](../sdk/tests/client/decryption.test.ts) · [Session lifetime](../sdk/tests/connection/session.test.ts) · [HTTP limits](../sdk/tests/connection/http.test.ts) · [Boot Proof lookup](../sdk/tests/connection/connect.test.ts) |
| SPR-QOS-07 | Turnkey signs the exact SDK bytes for the expected account. | The adapter uses raw Ed25519 for approvals. It refuses another account's signature and changed transaction messages. [Turnkey signer](../example/tests/turnkey.test.ts) |

The tests use fixtures and simulated attestation inputs. The
[service spec](../enclave/SPEC.md#key-custody-and-trust) describes the trust
required of Quorum operators and the release authorities.

## Mainnet release controls

| ID | Invariant | Coverage |
| --- | --- | --- |
| SPR-OPS-01 | An unapproved build cannot supply a production manifest. | The operator tool requires the reviewed source commit, expected GitHub workflow, protected source ref, and immutable image digest. [Provenance checks](../xtask/tests/stage.rs) |
| SPR-OPS-02 | The staged mainnet release cannot switch a serving app or replace the known Quorum domain. | Candidate selection permits the first deployment or resumption of the same deployment. The operator tool rejects a shared devnet identity, a different Quorum key, and a one-share manifest. [Release staging](../xtask/tests/stage.rs) · [Approved deployment](../xtask/tests/policy.rs) |
| SPR-OPS-03 | A release bundle cannot choose its own mainnet trust anchors. | The SDK binds the policy to the independently pinned domain, Quorum key, distinct authority threshold, maximum lifetime, and revocation floor. [Mainnet pins](../sdk/tests/protocol/mainnet-release.test.ts) |
| SPR-OPS-04 | The example validates RPC genesis before loading signing credentials. | Preflight rejects mainnet configuration before any network call. It rejects mainnet genesis in both modes and accepts only the devnet genesis for hosted mode. Local mode requires loopback. [Example preflight](../example/tests/setup.test.ts) |

## Native Nitro

| ID | Invariant | Evidence |
| --- | --- | --- |
| SPR-NITRO-01 | Readiness requires three distinct committed shares of the measured epoch for the current RSA recipient. All 20 three-slot subsets restore the seed. Missing, duplicate, foreign, malformed, oversized, wrong-recipient and wrong-commitment inputs cannot contribute a share. A failed request allows a subsequent valid boot. | [Bootstrap](../enclave/tests/unit/nitro_bootstrap.rs) · [Custody](../enclave/tests/unit/nitro_custody.rs) · AWS rehearsal |
| SPR-NITRO-02 | A restart, image update or custody rotation initializes fresh boot keys and preserves the original note keys. The same owner can decrypt the existing note. Another signer cannot. | [Bootstrap](../enclave/tests/unit/nitro_bootstrap.rs) · [AWS rehearsal](nitro/rehearsal.mts) |
| SPR-NITRO-03 | A host needs the right measured image, kernel, application and IAM role, and the exact share context. A new image cannot unwrap an old image's share. Key operators cannot rewrite the policy or create a grant. | [Policy and relay](nitro/test_kms_policy.py) · AWS denied unattested decrypt, old image-to-key mismatch and policy mutation |
| SPR-NITRO-04 | The host reads an ordered plan with six distinct KMS accounts and forwards three to six ciphertexts to the same attested RSA recipient. Each KMS context binds its own slot and the measured epoch. A denied key can be skipped without counting it toward the threshold. | [Relay](nitro/test_kms_policy.py). Cross-account integration rehearsal pending |
| SPR-NITRO-05 | Only a configured threshold of distinct valid release signatures can approve a route or measurement. Wrong network, seed, domain, signature, version, validity, malformed pin, ambiguous endpoint or unsigned field fails. | [Policy](../sdk/tests/attestation/nitro-policy.test.ts) · [Before authorization](../sdk/tests/client/nitro.test.ts) |
| SPR-NITRO-06 | Once accepted, a lower sequence, a different digest at the same sequence or a lower custody floor fails, including for a new SDK instance with the same checkpoint. Signed targets below the policy floor fail even with valid approvals. | [Policy](../sdk/tests/attestation/nitro-policy.test.ts) · [AWS rehearsal](nitro/rehearsal.mts). Integration must exercise its durable store across process restart and concurrent writers |
| SPR-NITRO-07 | AWS evidence names the expected PCR0–PCR3, freshness nonce, attested discovery and response-signing key. A modified signature, stale or future evidence, wrong root, expired chain, wrong algorithm, or swapped transport key fails. | [Evidence](../sdk/tests/attestation/nitro-evidence.test.ts) with a real disposable AWS document · [AWS rehearsal](nitro/rehearsal.mts) |
| SPR-NITRO-08 | An authorized target may fail over before a wallet signature. Clients session-bind the operation to the exact connection and verify its signed reply independently of routing. | [AWS rehearsal](nitro/rehearsal.mts) exercises a failed candidate, overlapping service on two Nitro hosts, promotion and retirement. Shared [reply-binding tests](../sdk/tests/connection/operations.test.ts). Multi-AZ and TLS ingress qualification pending |
| SPR-NITRO-09 | The native production artifact does not depend on `qos_core`, `qos_p256` or the affected Tokio version. OpenSSL and the existing SPR client agree on the P-256 envelope. Modified frames and the wrong key fail. | [Linux wire interop](../enclave/tests/unit/nitro_wire.rs) · [Native build](../enclave/native/Cargo.toml) |
| SPR-NITRO-10 | A measured rotation increments the custody epoch, restores the existing seed, and issues new shares solely to the six reviewed recipients. Wrong recipients, changed seed commitments, misordered packages, unsigned receipts and mixed epochs cannot authorize a new custody record. | [Custody](../enclave/tests/unit/nitro_custody.rs) · [Receipt verifier](../sdk/tests/attestation/nitro-custody.test.ts) · [Rotation admission](nitro/test_target_approval.py) |
| SPR-NITRO-11 | Before opening a recovery share, a custodian verifies the canonical receipt, two current target approvals, the measured build and the installed recovery and wrap policies. A changed receipt, EIF, destination key, key epoch, missing approval or widened policy stops release. | [Target approval](nitro/test_target_approval.py) · [KMS policy](nitro/test_kms_policy.py) |
| SPR-NITRO-12 | A custody commit requires six distinct custody accounts, two approvals and six recovery acknowledgements for the exact record. The first concurrent commit wins. A rotated record must preserve the seed and descend from the committed predecessor. | [Custody ledger](nitro/test_custody_ledger.py) · [Same-epoch share isolation](../enclave/tests/unit/nitro_custody.rs) |
| SPR-NITRO-13 | Only an attested activation or an explicit threshold-signed revocation can advance the wallet sequence and custody floor. Both persist before any wallet operation. A bad replica proof leaves the previous checkpoint usable. A late reply fails if the native session has expired or the wallet has already recorded a successor. | [Native client trust gate](../sdk/tests/client/nitro.test.ts) · [Operation replies](../sdk/tests/connection/operations.test.ts) · [Signed policy schema](../sdk/tests/attestation/nitro-policy.test.ts) · [Signing tool](../xtask/tests/nitro_sign.rs) |
| SPR-NITRO-14 | Clients sharing a browser origin and security domain serialize checkpoint updates. A session superseded by another client cannot send an operation. | [IndexedDB checkpoint tests](../sdk/tests/attestation/nitro-checkpoint.test.ts) · [Native client trust gate](../sdk/tests/client/nitro.test.ts) |
| SPR-NITRO-15 | Wallets read two authenticated policy heads from pinned buckets with distinct AWS owners. They accept agreement or the exact live successor and refuse an unavailable head, gap, fork or expired newest policy. Each write uses its bucket's ETag and checks the predecessor and live targets. | [Publication verifier](../sdk/tests/attestation/nitro-policy.test.ts) · [Native client trust gate](../sdk/tests/client/nitro.test.ts) · [Publishing tests](nitro/publication.test.mts). | SPR-NITRO-16 | Public attestation has a separate request budget and one blocking NSM call at a time. Cancelling the request cannot start another call prematurely. | SPR-NITRO-17 | Custody and target signers require provenance from the pinned repository and workflow for the exact reviewed ref, commit, network, executable, configuration, EIF and measurements. | SPR-NITRO-18 | Historical receipts verify locally against their epoch's pinned approval keys and their authenticated acknowledgement keys. Older approval keys cannot approve a new epoch.
